# ContentX — Outcome-First UX/UI Reframing & Workflow Experience

너는 현재 진행 중인 ContentX 프로젝트의
Lead Product Designer + UX Architect + Senior Full-Stack Engineer다.

IMPORTANT:

이것은 새로운 프로젝트를 만드는 작업이 아니다.

현재 ContentX repository에 이미 구현되어 있는 기능과 architecture를
최대한 보존하면서,

"사용자가 원하는 결과(Output)를 말하면
ContentX가 필요한 Workflow를 추천하고,
사용자가 이를 추가/삭제/수정한 후 실행할 수 있는
직관적인 Outcome-First Content Platform"

으로 UX/UI를 재구성하는 것이 이번 작업의 목표다.

RoleplayX는 ContentX의 일부 사용처일 뿐이다.

ContentX 자체가 독립적인 Content Engine / Content Platform으로
발전할 수 있어야 한다.

==================================================
1. CORE UX PRINCIPLE
==================================================

기존의 사용자 경험:

Content
→ Entity
→ Graph
→ Scenario
→ Projection

을 사용자가 직접 이해하고 조작하는 방식은 피한다.

새로운 UX의 핵심은:

USER INTENT
→ DESIRED OUTPUT
→ AI RECOMMENDED WORKFLOW
→ USER ADJUSTMENT
→ EXECUTION
→ OUTPUT

이다.

핵심 문장:

"사용자는 무엇을 어떻게 만들지 알 필요가 없다.
원하는 결과를 말하면 ContentX가 필요한 작업을 제안한다."

AI는 Workflow를 추천하지만 사용자가 최종 결정한다.

AI recommends.
User decides.


==================================================
2. FIRST — ANALYZE THE EXISTING PROJECT
==================================================

코딩하기 전에 현재 repository를 먼저 분석하라.

현재 구현된:

- frontend
- routing
- navigation
- pages
- components
- content domain
- AI domain
- scenario domain
- graph
- generation
- synthesis
- classification
- validation
- projection
- RoleplayX adapter
- versioning
- export
- API
- database
- existing workflows

를 실제 코드 기준으로 파악한다.

특히 현재 UX/UI가:

1. 사용자가 무엇을 해야 하는지 명확한가?
2. 처음 접했을 때 ContentX가 무엇인지 이해할 수 있는가?
3. Graph가 사용자에게 과도하게 노출되어 있는가?
4. 내부 architecture terminology가 사용자 UX에 노출되어 있는가?
5. 원하는 Output까지 도달하는 경로가 복잡한가?
6. 기존 기능을 사용자가 발견하기 어려운가?
7. 빈 화면에서 무엇을 해야 하는지 알기 어려운가?
8. Workflow를 사용자가 직접 설계해야 하는 부분이 있는가?

를 평가한다.

현재 구현을 확인하지 않고 추측해서 변경하지 마라.


==================================================
3. DO NOT REBUILD THE ENGINE
==================================================

이번 작업의 목적은 Content Engine을 새로 만드는 것이 아니다.

기존 ContentX의:

- Content Model
- Content Graph
- Generation
- Synthesis
- Scenario Graph Builder
- Projection
- RoleplayX Adapter
- Versioning
- Export
- API

등의 기능을 최대한 재사용한다.

현재 기능을 삭제하거나 재작성하기 전에 반드시:

- 왜 필요한지
- 어떤 기존 기능을 대체하는지
- migration risk가 무엇인지

확인한다.

==================================================
5. OUTPUT-FIRST UX
==================================================

사용자가 처음부터:

- Entity
- Relationship
- Graph
- Projection
- Canonical Model

을 선택하게 하지 마라.

대신 사용자가 원하는 결과를 선택하거나 자연어로 설명할 수 있도록 한다.

예:

"What do you want to create?"

또는:

"무엇을 만들고 싶으세요?"

선택 예:

- 🎬 영화 이야기
- 📖 소설
- 🎭 롤플레이
- 🚀 제품 반응 시뮬레이션
- 🎮 게임 콘텐츠
- 📢 광고 콘텐츠
- 🧩 새로운 콘텐츠 조합
- 📚 기존 콘텐츠 재구성
- ✨ 직접 설명하기


==================================================
6. OUTPUT INTENT
==================================================

사용자가 원하는 결과를 Output Intent로 정의한다.

예:

User:

"새로운 AI 노트북을 출시하려고 하는데
타겟 고객들이 어떻게 반응할지 알고 싶어요."

ContentX:

Output Intent:

Product Launch Reaction Simulation


필요한 요소를 AI가 분석한다.

예:

- Product
- Target Audience
- Persona
- Decision Factors
- Simulation Scenario
- Simulation
- Result Analysis


==================================================
7. AI WORKFLOW PLANNER
==================================================

Output Intent를 분석한 뒤
AI가 Recommended Workflow를 생성한다.

예:

Product Definition
        ↓
Target Audience
        ↓
Persona Generation
        ↓
Decision Factors
        ↓
Simulation Scenario
        ↓
Reaction Simulation
        ↓
Result Analysis


중요:

AI가 Workflow를 결정해서 강제하지 않는다.

AI가 "추천"한다.


==================================================
8. WORKFLOW STEP TYPES
==================================================

Workflow Step은 향후 확장 가능한 구조로 설계한다.

예:

- Input
- Generate
- Extract
- Analyze
- Transform
- Compose
- Remix
- Simulate
- Validate
- Compare
- Export
- Project


각 Step은:

- id
- type
- title
- description
- required
- recommended
- optional
- input
- output
- status
- dependencies

등을 표현할 수 있어야 한다.

현재 시스템에 이미 유사한 구조가 있다면 재사용한다.


==================================================
9. REQUIRED / RECOMMENDED / OPTIONAL
==================================================

Workflow의 각 단계는 사용자가 쉽게 이해할 수 있도록
다음 세 가지 상태를 지원한다.

Required
✓ 필수

Recommended
● 추천

Optional
○ 선택


예:

✓ Product Definition
✓ Target Audience
● Persona Generation
● Decision Factors
○ Competitor Analysis
✓ Simulation
● Result Analysis


==================================================
10. USER CONTROL
==================================================

사용자는 AI가 만든 Workflow를 수정할 수 있어야 한다.

각 Step에:

[ Edit ]
[ Remove ]

를 제공한다.

Workflow 전체에는:

[ + Add Step ]

을 제공한다.

예:

+ Add Step

선택:

- 경쟁사 분석
- 시장 분석
- Persona 추가
- 인터뷰 생성
- 역할극
- A/B 테스트
- 결과 비교
- 직접 입력


사용자가 Step을 제거하면
의존 관계가 깨지는 경우 이를 알려준다.

예:

"이 단계를 제거하면 Simulation에 필요한 Persona 정보가 없습니다."

[ 자동으로 대체 ]
[ 계속 진행 ]
[ 취소 ]


==================================================
11. WORKFLOW IS NOT THE CONTENT
==================================================

매우 중요하다.

Workflow와 Content를 혼동하지 마라.

Workflow:

"어떤 작업을 어떤 순서로 수행할 것인가"

Content:

"작업 결과로 생성/관리되는 실제 콘텐츠"

예:

Workflow:

Product
→ Audience
→ Persona
→ Simulation

Content:

Product A
Persona B
Scenario C
Simulation Result D


==================================================
12. CONTENT GRAPH SHOULD BE SECONDARY
==================================================

Content Graph는 삭제하지 않는다.

그러나 일반 사용자가 첫 화면부터 Graph를 이해해야 할 필요는 없다.

기본 UX:

Intent
→ Workflow
→ Workspace
→ Output

Advanced UX:

Advanced View
→ Content Graph
→ Entities
→ Relationships
→ Dependencies
→ Provenance
→ Versions


Graph는 강력한 전문가 기능으로 유지한다.

Beginner UX와 Advanced UX를 분리한다.

==================================================

먼저:

1. 현재 UI 분석
2. 현재 기능 분석
3. Output 정의

을 수행한다.

P0/P1 중 실제 구현 가능한 변경을 시작한다.

대규모 UI migration을 한 번에 하지 마라.


==================================================
32. ACCEPTANCE CRITERIA
==================================================

사용자가 ContentX를 처음 사용했을 때
다음 질문에 답할 수 있어야 한다.

"이 서비스로 무엇을 할 수 있지?"

→ Example Gallery 또는 Output 선택에서 즉시 이해할 수 있어야 한다.

"내가 원하는 결과를 어떻게 만들지?"

→ AI가 Workflow를 제안해야 한다.

"AI가 정한 대로 해야 하나?"

→ 아니다. Step을 추가/삭제/수정할 수 있어야 한다.

"Content Graph를 알아야 하나?"

→ 아니다.

"RoleplayX를 알아야 하나?"

→ 아니다.

"콘텐츠를 다른 형태로 사용할 수 있나?"

→ 결과 화면에서 즉시 다른 Output을 선택할 수 있어야 한다.

Content Graph

+
Workflow
+

+
Provenance

를 사용한다.

그러나 사용자에게는:

Intent
→ Recommended Workflow

→ Result

로 보여준다.

START
